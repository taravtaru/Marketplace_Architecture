# ADR-001: доменно-ориентированная декомпозиция

- Статус: принято
- Дата: 2026-10-02

## Контекст

Маркетплейс должен поддерживать пользователей двух ролей, каталог продавцов, персонализированную ленту, заказы, платежи и уведомления. Эти области различаются по нагрузке, скорости изменений и чувствительности данных. Слишком мелкая декомпозиция при этом создаст неоправданную распределенную сложность.

## Решение

Выделить шесть крупных бизнес-контекстов: User, Catalog, Feed, Order, Payment и Notification. Каждый реализуется автономным сервисом. API Gateway и Event Broker не содержат бизнес-источников истины и считаются инфраструктурой.

Граница может быть разделена дальше только при измеримой причине: независимой команде, конфликтующем профиле нагрузки, отдельной политике безопасности или высокой частоте изменений.

## Последствия

Положительные:

- сервисы соответствуют бизнес-языку и независимо развертываются;
- Feed масштабируется отдельно, Payment изолирует чувствительные данные;
- число сетевых границ меньше, чем при декомпозиции по сущностям.

Отрицательные:

- нужны устойчивые контракты, наблюдаемость и обработка сетевых сбоев;
- сквозные сценарии не могут полагаться на одну ACID-транзакцию;
- команде придется поддерживать инфраструктуру нескольких сервисов.
